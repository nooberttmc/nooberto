# Handoff: noobertt's music + Emberwake (for a new Claude session)

Paste this file into a new session (or point it at `HANDOFF.md` in the repo). It explains the project, the user's
standing preferences, where everything lives and what to do next.

## Who and what
- The user releases music as **noobertt** (artist tag on every MP3/MP4; the old name "sunkensol" is retired).
- Repo: `https://github.com/nooberttmc/nooberto`, branch **`claude/android-game-apk-w2q4io`** (all work is here; commit
  and push to this branch).
- Two projects in the repo:
  1. **Emberwake**: an Android roguelite game (`app/`, HTML canvas in a WebView; `Emberwake.apk` + `version.json` at the
     root feed the in-game updater). Current version **v4.5**. To ship a change: bump `versionCode`/`versionName` in
     `app/AndroidManifest.xml`, write `app/release-notes.txt`, run `app/build.sh` (Linux), commit `Emberwake.apk` +
     `version.json`. The phone then offers the update.
  2. **Music**, made with the **song-forge** skill (`skills/song-forge/`, also packed as `skills/song-forge.skill`).
     Read `skills/song-forge/SKILL.md` before any music work: it has the workflow and 37 hard-won lessons.

## The user's standing preferences (follow these)
- **Every song is built for FL Studio** (SKILL.md lesson 37): the user wants each song to open in FL as if it was made
  there (instruments playing MIDI, FL's own effects), not bounced audio. Ship an FL kit with every song.
- **House guitar and piano**: whenever a song has guitar or piano, use the ones in SKILL.md lesson 23 (the apricity
  guitar config; the Salamander SFZ grand for piano).
- Mixing: about -11 LUFS, true peak <= -1 dBTP on every delivered file (MP3 and MP4). Contrast by colour, not volume.
- Releases: MP3 + MP4 visualizer video + thumbnail (single colour, pixel art, no gradients); short one-word lowercase
  titles with a period ("crucible.").
- The user wants things to "make no mistakes": check your work (measure audio, screenshot UI) before saying it's done,
  and say plainly what you could not check.

## What to do next (in this order)
1. **Build ardor in FL Studio** on the user's computer (needs computer use / desktop control in the Claude desktop app).
   The kit is `ardor - FL Studio kit.zip` (the user has it; it's regenerated by the steps in its guide):
   - `ardor. (FL Studio).mid`: notes, velocities, tempo map, pedal baked into note lengths, Retuned keyswitch (C#0).
   - `ardor hall (impulse).wav`: the song's exact hall reverb for Fruity Convolver.
   - `HOW TO BUILD IT IN FL STUDIO.txt`: every step and setting (sfizz + Salamander SFZ, mixer routing, Parametric EQ 2,
     Fruity Limiter comp/limit, Stereo Shaper, section-lift automation, master).
   - `ardor.mp3`: the reference to compare against.
   Downloads needed first: sfizz VST3 (https://sfz.tools/sfizz/downloads) and the Salamander Grand Piano V3 SFZ
   (https://github.com/sfzinstruments/SalamanderGrandPiano). Note anything in the guide that turns out wrong in FL
   (menu names, plugin behaviour) and fix the guide and SKILL.md lesson 37.
2. **Make FL kits for crucible and apricity** the same way. Harder parts: the guitars (Guitarix JCM800 + DS-1 amp sim
   in `scripts/reamp.py`, no FL twin: use FL's amp/distortion plugins or a free amp-sim VST, plus a cabinet impulse
   rendered from `reamp.cabinet()`), the drums (the breaks chopped into slices: ship the slices as samples or an SFZ
   mapped to the "Break Slices" MIDI track, pitch = slice number from C3), and the synth parts (ship as samples/SFZ).
   Orchestra parts use MuseScore General (program numbers are in `stems/events.json`); FL's Fruity Soundfont Player
   needs .sf2, so convert the .sf3 (e.g. with Polyphone) or ship just the needed presets.
   `export_midi.py ... --fl` makes the FL-ready MIDI.
3. Then keep making songs with song-forge, FL-first.

## Where the tools run
- The song-forge pipeline (FluidSynth, Guitarix, headless Chromium, ffmpeg) is built for **Linux**. On Windows, run it in
  **WSL (Ubuntu)**: `bash skills/song-forge/scripts/setup.sh` and `setup.sh --grand`, or keep rendering in a Claude
  cloud session. FL Studio itself runs on Windows/macOS.
- Checks before sending a song: `node scripts/check_notes.js song.js`, `node scripts/density_check.js song.js`,
  `node scripts/check_playable.js song.js` (piano), loudness/true peak with `scripts/analyze.py`.
- Self-tests: `python3 skills/song-forge/scripts/test_piano_render.py`, `python3 skills/song-forge/scripts/test_export_midi.py`.
